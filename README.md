# frontend-sample — SPA + Feature-Sliced Design

A **Vite + React** single-page application template organized with **Feature-Sliced Design (FSD)**. Use it as the baseline for **UI-only microservices**: business APIs and auth live in **your separate backends**; this repo stays focused on routing, state, and presentation.

- **Auth:** local dev can use the built-in mock; production services should use `VITE_AUTH_MODE=keycloak` for the shared Keycloak SSO flow, or implement the `backend-session` adapter behind [`src/shared/lib/client-auth.ts`](src/shared/lib/client-auth.ts).
- **APIs:** configure `VITE_API_URL` (gateway or domain service). See [`docs/api-contracts.md`](docs/api-contracts.md) for contract-first integration.
- **Template upgrades:** see [`CHANGELOG-template.md`](CHANGELOG-template.md), [`docs/migrations/`](docs/migrations/), and tag releases (for example `template/v1.1.0`) for downstream forks.

## 🏗️ Architecture Overview

This project follows **Feature-Sliced Design (FSD)** principles, organizing code into layers:

```
src/
├── app/           # Application initialization, providers, root components
├── pages/         # Page components (composed of widgets/features)
├── widgets/       # Complex UI blocks (composed of features/entities)
├── features/      # User interactions and business features
├── entities/      # Business entities (user, session, etc.)
└── shared/        # Reusable code (UI kit, API, utils, configs)
```

## 🚀 Getting Started

### 1. Install Dependencies

```bash
npm install
```

### 1.1. Install New Features (Recommended)

To enable all production-ready features, install these additional dependencies:

```bash
npm install --save-dev @sentry/react @playwright/test msw rollup-plugin-visualizer eslint-plugin-jsx-a11y eslint-plugin-import eslint-import-resolver-typescript

# Install Playwright browsers
npx playwright install

# Initialize MSW
npx msw init public/ --save
```

> **Note:** See [INSTALLATION_GUIDE.md](./INSTALLATION_GUIDE.md) for detailed installation instructions and troubleshooting.

### 2. Environment variables

Copy [`.env.example`](.env.example) to `.env` and set at least:

| Variable                  | Purpose                                                                                |
| ------------------------- | -------------------------------------------------------------------------------------- |
| `VITE_API_URL`            | Base URL for your HTTP API (gateway or service).                                       |
| `VITE_AUTH_MODE`          | `mock`, `keycloak`, or `backend-session`. Use `keycloak` for shared IAM/SSO.           |
| `VITE_USE_MOCK_AUTH`      | Backward-compatible dev flag for localStorage mock auth. Prefer `VITE_AUTH_MODE=mock`. |
| `VITE_KEYCLOAK_URL`       | Keycloak base URL when `VITE_AUTH_MODE=keycloak`.                                      |
| `VITE_KEYCLOAK_REALM`     | Keycloak realm name.                                                                   |
| `VITE_KEYCLOAK_CLIENT_ID` | Public frontend client id registered in Keycloak.                                      |
| `VITE_USE_MOCK_DATA`      | `true` to enable MSW in dev (see `src/shared/api/mocks/browser.ts`).                   |
| `VITE_E2E_BASE_URL`       | Optional Playwright `baseURL` (defaults to `http://localhost:4173`, matching `playwright.config.ts` webServer). |

For **multiple backends** (micro-UI per domain), add more `VITE_*` URLs and small factories under `src/shared/api/` instead of hardcoding URLs inside features.

### 3. Initialize Husky

```bash
npm run prepare
```

This sets up Git hooks. The pre-commit hook will automatically run ESLint and Prettier on staged files.

### 4. Run Development Server

```bash
npm run dev
```

Visit `http://localhost:3000`

## 🔐 Authentication and SSO

This template does **not** ship Prisma, ORM, or in-repo auth servers. It provides a frontend auth facade that can run in mock mode for local development or Keycloak mode for shared IAM/SSO. See [`docs/auth-keycloak.md`](docs/auth-keycloak.md) for the Keycloak setup guide.

### Dev mock (optional)

Use `VITE_AUTH_MODE=mock` for local development. The mock stores demo users in `localStorage` — **never** use it in production.

### Keycloak SSO

Use `VITE_AUTH_MODE=keycloak` and configure `VITE_KEYCLOAK_URL`, `VITE_KEYCLOAK_REALM`, and `VITE_KEYCLOAK_CLIENT_ID`. The adapter uses Authorization Code + PKCE, keeps tokens in memory through `keycloak-js`, and refreshes the access token before API calls.

### Route protection

Protected routes use TanStack Router `beforeLoad` with [`authGuard`](src/shared/lib/route-guards.ts) (see [`src/routes/dashboard.tsx`](src/routes/dashboard.tsx)).

### Backend-owned sessions

If a service uses a BFF or server-owned session instead of Keycloak directly, implement the `backend-session` adapter behind the [`authClient`](src/shared/lib/client-auth.ts) facade. Keep the same surface shape so `useSession`, route guards, and API token injection remain stable.

### Client usage

Use the `authClient` from `@/shared/lib/client-auth`:

```tsx
import { authClient } from '@/shared/lib/client-auth'

// Sign in
await authClient.signIn.email({ email, password })

// Sign out
await authClient.signOut()

// Get session
const session = await authClient.getSession()
```

### Using Session Hook

The `useSession` hook from `@/entities/session/api/use-session` provides reactive session state:

```tsx
import { useSession } from '@/entities/session/api/use-session'

function MyComponent() {
  const { data: session, isLoading } = useSession()

  if (isLoading) return <div>Loading...</div>
  if (!session) return <div>Not authenticated</div>

  return <div>Hello, {session.user.email}</div>
}
```

## 🗺️ TanStack Router + FSD Pages Mapping

TanStack Router uses **file-based routing** in the `src/routes/` directory. Each route file imports and uses components from the FSD `pages/` layer.

### Mapping Pattern

```
src/routes/index.tsx     → src/pages/home/index.tsx
src/routes/login.tsx     → src/pages/auth/login/index.tsx
src/routes/dashboard.tsx → src/pages/dashboard/index.tsx
```

### Route File Structure

```tsx
// src/routes/example.tsx
import { createFileRoute } from '@tanstack/react-router'
import { ExamplePage } from '@/pages/example' // Import from pages layer

export const Route = createFileRoute('/example')({
  component: ExamplePage, // Use the page component
  // Optional: loaders, search validation, etc.
})
```

### Best Practices

1. **Route files** (`src/routes/`) should be thin - they only define routing configuration
2. **Page components** (`src/pages/`) contain the actual UI and business logic
3. Pages can compose widgets and features from other FSD layers
4. Use route `beforeLoad` (and loaders) for auth checks and prefetch

## 🪝 Git Hooks (Husky + lint-staged)

### Configuration

- **Husky**: Configured in `.husky/pre-commit`
- **lint-staged**: Configured in `package.json`

### What It Does

Before each commit, Husky runs `lint-staged`, which:

- Runs ESLint with auto-fix on staged `.ts` and `.tsx` files
- Runs Prettier on staged files (`.ts`, `.tsx`, `.json`, `.css`, `.md`)

### Scripts

```bash
# Development
npm run dev           # Start dev server

# Build
npm run build         # Build for production (generates bundle report)
npm run start         # Preview production build

# Code Quality
npm run lint          # Run ESLint
npm run lint:fix      # Run ESLint with auto-fix
npm run format        # Format all files with Prettier
npm run format:check  # Check formatting without fixing
npm run typecheck     # Regenerates route tree (pretypecheck) then tsc --noEmit

# Testing
npm run test          # Run unit tests (watch mode)
npm run test:run      # Run unit tests (single run)
npm run test:coverage # Run tests with coverage report
npm run routes:generate # Refresh TanStack Router src/routeTree.gen.ts
npm run test:e2e       # Run E2E tests (Playwright)
npm run test:e2e:ui    # Run E2E tests with UI
npm run test:e2e:chromium  # Chromium only (matches CI)
```

## 🎯 FSD Layer Guidelines

- **app/**: App initialization, global providers
- **pages/**: Full page components, route entry points
- **widgets/**: Complex UI blocks (header, sidebar, etc.)
- **features/**: User interactions (sign-in, create-post, etc.)
- **entities/**: Business entities (user, post, session, etc.)
- **shared/**: Reusable utilities, UI components, API clients

For more on FSD: https://feature-sliced.design/
